# Stored formats

Names that the stored results of the thesis runs depend on. The code keeps them unchanged, even
where they contain a word the documentation rules exclude (for example the columns `arm` and
`operating_point`, or the retrieval index key `exemplar`), so that every stored file can be read
and every result folder can be extended by a new run. The lists below were read off the stored
result files.

## Stored values

| Kind | Values |
|---|---|
| Retrieval index | `exemplar` (synthetic sentences), `ontology_r3` (term information) |
| Pooling operator | `P0`, `P1`, `P2`, `P3_1`, `P3_2`, `P3_S`, `P4`, `lse_beta1`, `LRGate` |
| Prompt | `p0_baseline` (Free Listing), `q2_sentence_last` (HPO-Guided), `q4_span_json` (Evidence Spans), `q7_recall` (Recall-First) |
| Normaliser | `phenobert_raw`, `phenobert_candidates`, `dictionary`, `sapbert` |
| Juror | `apertus`, `deepseek`, `intelligent_internet`, `openbiollm`, `llama`, `medpsy`, `medgemma`, `phi4` |
| Cohort | `hcy`, `gsc`, `gsc206`, `gsc_raghpo`, `gsc_raghpo_ann`, `gsc_2024_eval_206` |
| Method | `treephenorag`, `phenojury`, `phenojury_core3`, `phenobert`, `raghpo_8b`, `raghpo_70b`, `autopcr_8b`, `autopcr_70b` |
| Jury configuration | `full_pool`, `fixed:core3`, `fixed:core3swap`, `phenojury` |
| Ablation variant | `V0` to `V3` |
| False-positive category | `no_gold`, `invalid`, `ancestor`, `descendant`, `sibling`, `same_branch`, `unrelated` |
| Recall bucket | `pruning`, `retrieval`, `judgement`, `pooling`, `residual` |
| Curation source | `daphne`, `holistic`, `marc2` in stored logs (read as `daphne`, `prior_annotation`, `prior_annotation_2`) |
| Thesis interface | file stems `tab_*`, `fig_*`, `num_*`, their LaTeX labels and the `\chThree*`, `\chFour*`, `\chFive*` macros |
